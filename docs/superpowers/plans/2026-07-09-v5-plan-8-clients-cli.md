# spotDL v5 `apps/cli` — Generated Clients, CLI & v4 Compat Shim (Plan 8 of 11)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the `apps/cli` skeleton into the full `spotdl` command-line tool of spec §7. This plan ships: (1) the **generated Python API + WS client** — a build artifact produced from `apps/server`'s `openapi.json` (Plan 5/6) + `ws-protocol.json` (Plan 7); handwritten API clients are forbidden (spec §3); (2) **`SpotdlClient`** — a thin, typed façade over the generated client with **two transports** (remote HTTPS base URL, or in-process/loopback **embedded** server) — the single seam the CLI *and* the Plan 9 TUI/view-models build on; (3) the full **command surface** (`download`, `search`, `sync`, `save`, `meta`, `url`, `web`, `auth login|logout|status`, `config get|set|edit`, `server`, bare-query sugar, plus `ffmpeg download`); (4) the **v4 compat shim** — an argv preprocessor with a table-driven translation layer that doubles as the migration-guide source (spec §12); (5) **`.spotdl` v4→v2 auto-migration**; and (6) the downloader UX (Rich progress, per-track failure collection, exit codes). The TUI itself is **Plan 9** (this plan only builds the client/view-model seam it consumes and stubs `spotdl tui`); the bundled web UI is **Plan 10** (this plan stubs `spotdl web`'s static-asset message until then).

**Architecture (hard rule — spec §3, machine-enforced):** dependency direction is `core ← server ← cli`. `apps/cli` **never imports `spotdl_core`** (import-linter contract `no_cli_core` already forbids it in `.importlinter`). The CLI reaches all functionality through the **server API** — over HTTPS (remote) or an in-process/loopback **embedded** server (`spotdl_server.app.create_app`, which the CLI *is* allowed to import: `cli → server` is an allowed layer). Local downloads therefore run **via the embedded server's engine**, never by importing `spotdl_core.download`. The generated client, the `SpotdlClient` façade, and every command consume only the server's typed API. No provider/matching/download logic ever lives in `apps/cli` — new data needs grow the server API (benefiting web + TUI too).

**Tech Stack:** Python 3.13, Typer (CLI framework, already a dep), Rich (progress, already a dep), httpx (already a dep), **httpx-ws** (WebSocket progress consumption over the same httpx transport), **platformdirs** (config/data dirs), **tomlkit** (round-trip-preserving TOML config read/write), uvicorn (loopback embedded server + `spotdl server`; already a server transitive dep, declared explicitly). Client generation (build-time, root dev group): **openapi-python-client** (HTTP client from `openapi.json`) + **datamodel-code-generator** (pydantic v2 WS message models from `ws-protocol.json`). Tests: pytest + pytest-asyncio, Typer `CliRunner`, httpx `ASGITransport` (fast in-process embedded read path), an ephemeral loopback uvicorn for WS/download integration, **respx** (already in the dev group) for remote-transport HTTP. The default suite is **fully offline**: the embedded server is booted with a **fake provider registry** (the Plan 5 fake-registry seam, reached from CLI tests via the app-construction hook in Task 4); no real provider network, no yt-dlp/ffmpeg, no Postgres.

## Download-flow decision (CONTRACT — how "community resolve + local audio" reconciles with Plan 7)

Spec §7: "community server for resolve/search/match/lyrics; downloads **always local** via the embedded server's engine." Two transports exist (see the transport CONTRACT): a **resolution transport** (community remote by default; embedded on `--offline`/fallback) used by the read commands, and a **download executor** that is **always the embedded server** (hosted mode hard-disables downloads — 403 `downloads_disabled`, router not mounted).

- `spotdl download` / `spotdl sync` submit the **query/URL** to the **embedded** server's `POST /downloads`; the embedded server resolves + matches with the **same layered provider stack** (spec §2: anonymous-token Spotify client **primary** — *no operator credentials required* — → operator-credential fallback → Deezer/iTunes/MusicBrainz → permanent SQLite snapshot cache) and downloads. This is the one code path Plan 7 provides, and it is why local downloads do **not** need shipped Spotify credentials.
- The **read commands** (`search`, `url`, `save`, entity views, `meta` tag-lookup, lyrics, match voting) use the **resolution transport** (community by default) for richer/cached metadata, `degraded_sources` visibility, and community-verified matches.
- **v1 documented limitation + forward hook:** community-cached metadata and community-verified match pins are **not** injected into the embedded download path in v1 (the embedded server resolves the download locally). A future enhancement — an embedded metadata resolver that proxies to the community server, or a "download a pre-resolved track+match" submission mode — is noted, not implemented; it is out of scope here and, per spec §13, would require a spec update. This keeps Plan 8 buildable on Plans 5–7 exactly as landed and never re-implements resolve/match in the CLI.

## THE CONTRACTS (authoritative — verbatim; implementers copy, only internals are free)

### CONTRACT A — Client-generation pipeline (`make clients`)

**Tool choice — PICKED: `openapi-python-client` (HTTP) + `datamodel-code-generator` (WS models). Justification:**
- **`openapi-python-client`** is the maintained, deterministic standard for turning an OpenAPI 3.1 document into a typed Python client. Critically, its generated client is built on **httpx** and accepts a **caller-supplied `httpx.AsyncClient`** (`Client.set_async_httpx_client` / `get_async_httpx_client`), so the *same generated code* drives both transports: a real `AsyncClient(base_url=...)` for remote and an `AsyncClient(transport=httpx.ASGITransport(app))` for in-process embedded. It emits per-operation modules with typed models and typed error handling — satisfying spec §3 "generated, typed errors; handwritten clients forbidden." A "thin generated wrapper" (models via `datamodel-code-generator` + a hand-written transport) was **rejected**: the transport would be a handwritten API client, which spec §3 forbids, and it would drift from the schema.
- **WS is not in OpenAPI.** FastAPI does not describe WS routes, so `ws-protocol.json` (Plan 7's committed JSON-Schema artifact) is fed to **`datamodel-code-generator`** to emit pydantic v2 models for the `WsMessage` union. This mirrors the server's own `TypeAdapter(WsMessage).json_schema()` source of truth, so client and server WS types cannot silently diverge.

**Generated code location — PICKED: `apps/cli/src/spotdl_cli/_generated/`. Justification:** the **only** consumer of the Python client is `apps/cli` (the CLI now + the Plan 9 TUI, both in this package); `apps/web` uses a separate generated **TypeScript** client (Plan 10). Nesting it inside `spotdl_cli` avoids minting a new published PyPI package + version for an internal artifact and keeps the client versioned lockstep with the CLI. The existing import-linter roots already cover `spotdl_cli`; because the generated code imports only `httpx`/`attrs`/`pydantic` (never `spotdl_core`), the `no_cli_core` contract stays green (Task 1 asserts this). Layout:

```
apps/cli/src/spotdl_cli/_generated/
├─ __init__.py                 # hand-written 2-line re-export shim (held to standards): exposes the api pkg + ws models
├─ api/                        # openapi-python-client output, `--meta none` (module tree only, no pyproject)
│  └─ spotdl_api_client/       # models/, api/<tag>/<operation>.py, client.py, errors.py, types.py
└─ ws_models.py                # datamodel-code-generator output: WsMessage union + member models
```

**Lint/type treatment — DECIDED: exclude generated code from ruff + mypy, keep it in the import-linter graph.** Add `apps/cli/src/spotdl_cli/_generated/` to `[tool.ruff] extend-exclude` and `[tool.mypy] exclude` (root `pyproject.toml`). Rationale: generator output is third-party-style code that will not pass our `--strict`/`(E,F,I,UP,B,SIM)` bars and would churn on every regen; it is instead validated by the **in-sync test** (below) + the generator's own `ruff format` post-processing. It stays in the import-linter graph so a stray `spotdl_core` import in generated code trips `no_cli_core`. The **`SpotdlClient` façade and everything else** are hand-written and fully held to standards.

### CONTRACT B — Transport abstraction + `SpotdlClient` façade (the Plan 9 seam)

```python
# spotdl_cli/transport.py   (hand-written; held to standards)
DEFAULT_API_URL = "https://api.spotdl.org"   # community server; OVERRIDABLE via config/env/--api-url.
# NOTE: placeholder. The real community URL is pinned in Plan 11 (spec §12). MUST NOT ship as a
# localhost stub, and localhost is NEVER the default.

class Transport(Protocol):
    """The seam SpotdlClient sits on. Yields an httpx.AsyncClient for request/response and a
    ws-connect for progress. TUI/view-models (Plan 9) depend on SpotdlClient, not on this."""
    @property
    def http_base(self) -> str: ...          # e.g. "https://api.spotdl.org" or "http://127.0.0.1:<port>"
    @property
    def ws_base(self) -> str: ...            # "wss://..." or "ws://127.0.0.1:<port>"
    def http_client(self) -> httpx.AsyncClient: ...
    @asynccontextmanager
    def ws_connect(self, path: str) -> AsyncIterator[AsyncWebSocketSession]: ...   # httpx-ws
    async def aclose(self) -> None: ...

class RemoteTransport:
    """HTTPS base URL + optional Bearer PAT. WS via httpx-ws over wss."""
    def __init__(self, base_url: str, *, token: str | None = None,
                 timeout: float = 30.0) -> None: ...

class EmbeddedTransport:
    """In-process embedded-mode server (SQLite in the platformdirs data dir).
    Two internal modes (one façade): a fast in-process httpx.ASGITransport for pure
    request/response, and a lazily-started loopback uvicorn (127.0.0.1, ephemeral port)
    when WS/downloads are needed (ASGITransport cannot carry WebSockets). `app_factory`
    is the TEST SEAM: tests inject a factory that builds create_app with a fake registry."""
    def __init__(self, settings: Settings, *, enable_downloads: bool = False,
                 app_factory: Callable[[Settings], ASGIApp] = _default_app_factory) -> None: ...
```

        # resolution = remote-or-embedded per policy; downloads = ALWAYS embedded.

- **`*View` types** are small hand-written frozen dataclasses/pydantic models in `spotdl_cli/views.py` — a **stable presentation contract** that decouples the CLI + TUI from the generated model shapes (so a client regen doesn't ripple into every command/screen). Mapping generated-model → View lives in `SpotdlClient`. **This View layer is the seam Plan 9's view-models build on.** Plan 9 adds view-models that call `SpotdlClient` and expose Textual-friendly state; it adds **no** new transport or client code.
- Every method translates a non-2xx `ErrorEnvelope` into a typed `ApiError(code: ErrorCode, message, detail, status)` (CONTRACT E). `WS_PROTOCOL_VERSION` is read from the generated `ws_models`/artifact constant.

### CONTRACT C — Connectivity policy (`--offline`, fallback, warning copy)

Resolution transport selection, evaluated in `SpotdlClient.from_config`:
1. **`--offline` (or `offline = true` in config, or `SPOTDL_OFFLINE=1`)** → resolution transport = **embedded**. No network attempt; no warning.
2. **Otherwise** → resolution transport = **remote** at `cfg.api_url` (default `DEFAULT_API_URL`). A cheap `GET /health` (2 s connect timeout) probes reachability at construction. If it fails with a **connection/timeout/DNS error or a 5xx**, fall back to **embedded** for this run and print **exactly** (to stderr, Rich):

   `warning: couldn't reach the spotDL community server at {api_url} ({reason}); using the offline embedded server for this run. Metadata may be thinner and slower. Pass --offline to silence this, or set a server with `spotdl config set api_url <url>`.`

   A 4xx (other than 401) from `/health` is treated as reachable (server is up). A 401 on an authed call is surfaced as `ApiError(authentication_required)`, **not** a fallback.
3. **Downloads transport is ALWAYS embedded**, independent of 1–3 (spec §7: downloads always local). `need_downloads=True` boots it with `enable_downloads=True` (loopback uvicorn for WS).
4. **`--api-url URL`** (global option) overrides `cfg.api_url` for the run. `localhost`/`127.0.0.1` is accepted when the user sets it explicitly, but is **never** the shipped default (spec §12).
5. **`spotdl auth *` is remote-only — it NEVER falls back to embedded** (the embedded server is authless per spec §4; silently targeting it would "succeed" against nothing). `from_config(..., require_remote=True)` (used only by the auth commands) disables rules 1–2's embedded paths and fails fast instead:
   - with `--offline` (or config/env offline): print **exactly** `error: `spotdl auth` needs the community server and can't run with --offline.` → exit `USAGE` (2);
   - when the probe finds `cfg.api_url` unreachable: print **exactly** `error: can't reach the spotDL server at {api_url} ({reason}) — `spotdl auth` needs it. Check your connection or set a server with `spotdl config set api_url <url>`.` → exit `TRANSPORT` (3).

### CONTRACT D — Config file & credentials (platformdirs; precedence CLI > env > file > defaults)

- **Config file:** `platformdirs.user_config_dir("spotdl", appauthor=False) / "config.toml"` (e.g. Linux `~/.config/spotdl/config.toml`, macOS `~/Library/Application Support/spotdl/config.toml`, Windows `%LOCALAPPDATA%\spotdl\config.toml`). TOML, read/written with **tomlkit** (preserves comments/formatting for `config edit`). Missing file ⇒ all defaults.
- **Data dir:** `platformdirs.user_data_dir("spotdl", appauthor=False)` — the embedded SQLite (`spotdl.db`), the ffmpeg binary (`ffmpeg/`), and provider cache live here. Passed to the embedded `Settings(data_dir=...)`.
- **Credentials (PATs):** stored **separately** in `<config_dir>/credentials.toml`, file mode `0600`, keyed by server origin so multiple servers can be logged in:
  ```toml
  [servers."https://api.spotdl.org"]
  token = "spdl_pat_..."
  email = "user@example.com"     # for `auth status` display only
  ```
  Never written to the shared `config.toml`; never logged.
- **`CliConfig`** (`spotdl_cli/config.py`, pydantic model) fields (TOML keys): `api_url: str = DEFAULT_API_URL`, `offline: bool = False`, `output_dir: Path | None = None` (**wired**: maps to the embedded server's `SPOTDL_LIBRARY_PATH` / `Settings.library_path`, the engine's output root; `None` → the server default `data_dir/"music"` — overridden per invocation by a directory prefix in `--output`, see the Task 7 option table), `output_template: str = "{artists} - {title}.{output-ext}"`, `format: str = "mp3"`, `bitrate: str = "auto"`, `overwrite: str = "skip"`, `restrict: str = "none"`, `threads: int = 4`, `ffmpeg: str | None`, `ffmpeg_args: str = ""`, `ytdlp_args: str = ""`, `cookie_file: Path | None`, `proxy: str | None`, `embed_lyrics: bool = True`, `generate_lrc: bool = False`, `sponsor_block: bool = False`, `id3_separator: str = "/"`, `log_level: str = "INFO"`.
- **Precedence (CONTRACT):** for any effective setting, **CLI flag > environment (`SPOTDL_*`) > `config.toml` > built-in default**. Implemented by `load_config()` returning a `CliConfig` merged from file+env, then each command layering explicit flags on top (a flag left at its Typer default `None` does not override). The embedded `Settings` the CLI builds reuse the same `SPOTDL_` env prefix, so env flows through consistently.

### CONTRACT E — Exit codes + server-envelope rendering

```python
# spotdl_cli/errors.py
class ExitCode(IntEnum):
    OK = 0                 # success
    DOWNLOAD_FAILURES = 1  # >=1 track/entity failed, or NoMatch/NotFound for the requested item
    USAGE = 2              # bad arguments (Typer default for BadParameter/UsageError)
    TRANSPORT = 3          # server unreachable AND offline resolve also failed; 5xx; downloads_disabled; rate_limited
    AUTH = 4               # authentication_required / forbidden / invalid_token / token_expired

class ApiError(Exception):
    code: ErrorCode; message: str; detail: dict | None; status: int
```
Envelope-code → (human message, exit code) table, applied by a top-level Typer error handler (`render_api_error`):

| `ErrorCode` | Human message (Rich, stderr) | Exit |
|---|---|---|
| `not_found` | `not found: {detail or message}` | 1 |
| `no_match_found` | `no matching audio found for "{detail.track or message}" — try `spotdl search`, or submit a match URL for it` | 1 |
| `unsupported_url` | `unsupported URL or query: {message}` | 1 |
| `unsupported_entity` | `can't download a {detail.entity_type} — pass a track, album, or playlist` | 1 |
| `not_an_audio_target` | `that URL isn't a downloadable audio source: {message}` | 2 |
| `download_failed` | `download failed at {detail.step}: {detail.reason or message}` | 1 |
| `provider_unavailable` | `provider {detail.provider} is unavailable right now — results may be degraded; try again later` | 3 |
| `provider_auth_error` | `provider {detail.provider} rejected the server's credentials — the server operator needs to fix this` | 3 |
| `downloads_disabled` | `downloads are disabled on this server (hosted mode); run downloads locally` | 3 |
| `rate_limited` | `rate limited by the server; retry after {detail.retry_after}s` | 3 |
| `validation_error` | `invalid request: {message}` | 2 |
| `authentication_required` | `this needs an account — run `spotdl auth login`` | 4 |

Batch downloads never abort on a per-track failure: failures are collected and, at the end, a Rich summary lists each failed track + step; the process exits `DOWNLOAD_FAILURES` if any failed (mirrors v4 + spec §10). `--save-errors PATH` writes the failure details; `--print-errors` forces the full list to stdout even when few.

### CONTRACT F — v4 compat shim (argv preprocessor + translation table)

The shim is a pure function `translate_v4_argv(argv: list[str]) -> ShimResult` run in `main()` **before** Typer parses. `ShimResult` is either `Rewritten(new_argv, notices: list[str])` or `Dropped(flag, pointer)` or `Unchanged`. Because v4 and v5 share operation names (`download|save|sync|meta|url|web`) and many flag names, the shim is a **normalizer + validator**, not a separate parser. Row kinds (exactly four):
- **SAME** — token passes through unchanged.
- **RENAME** — token rewritten to its v5 form.
- **SOFT-DROP** — the flag is now meaningless but harmless (a v4 no-op whose behavior is automatic in v5): the token (and its value, if any) is **stripped**, a warning is printed (`warning: `{v4_flag}` is obsolete in spotdl v5 and was ignored — {pointer}`), and execution **continues**. Reserved for flags whose removal cannot change the outcome the user asked for.
- **DROP** — the flag named behavior v5 genuinely no longer does client-side: print `error: `{v4_flag}` was removed in spotdl v5. {pointer}` and exit `USAGE` (2). Drops take precedence and fail fast.

Bare `spotdl <query>` (no operation) and `spotdl download <query>` both map to v5 `download` (bare-query sugar). If any RENAME (or a legacy positional form) fired, print **one** line to stderr: `note: translated a spotdl v4 invocation → `spotdl {new_form}` (see the v4→v5 migration guide).` then hand `new_argv` to Typer. The table is a single module-level data structure (`V4_FLAG_TABLE`) that is **also the migration-guide source** (spec §12): a docs build renders it to Markdown. Tests iterate every row.

**Translation table (v4 `arguments.py` → v5). Operations:** `download|save|sync|meta|url` map to the identically named v5 command; `web`→`spotdl web`; v4 default (no op) → `download` (bare-query sugar). ### CONTRACT G — `.spotdl` v4→v2 auto-migration

`spotdl_cli/savefile.py::load_save_file(path) -> SaveFileV2`. Detect by top-level JSON type: a **list** ⇒ v4 (bare array of `Song.asdict`); an **object with `"version": 2`** ⇒ v5, parse directly; anything else ⇒ `ApiError(validation_error, "unrecognized .spotdl file")`. v4→v2 rules (per song dict → `SaveFileSong`):

| `SaveFileSong` field | v4 source key(s) | Rule |
|---|---|---|
| `name` | `name` | copy |
| `artists` | `artists` | list copy |
| `artist` | `artist` else `artists[0]` | main artist |
| `album_name` | `album_name` | copy |
| `album_artist` | `album_artist` | copy |
| `duration_ms` | `duration` | v4 `duration` is **seconds (float)** → `round(duration*1000)` |
| `isrc` | `isrc` | copy |
| `explicit` | `explicit` | copy |
| `track_number`/`disc_number`/`disc_count`/`track_count` | same | copy |
| `year` | `year` | copy |
| `date` | `date` | copy |
| `genres` | `genres` | list copy (`[]` if absent) |
| `publisher`/`copyright_text` | `publisher`/`copyright` | copy |
| `popularity` | `popularity` | copy |
| `cover_url` | `cover_url` | copy |
| `track_url` | `url` | v4 `url` = canonical (Spotify) track URL |
| `provider`/`provider_id` | — | `null` (v4 didn't record the metadata provider distinctly; these are Optional on `SaveFileSong`) |
| `list_name`/`list_position`/`list_length` | `list_name`/`list_position`/`list_length` | copy if present |
| `match` | `download_url` (+ `song_id`) | build `SaveFileMatch{url=download_url, provider_id=song_id, provider=infer_audio_provider(download_url), verified=false}` when `download_url` present, else `null`. **`SaveFileMatch.provider` is required non-Optional in Plan 7's model, so it must never be null.** `infer_audio_provider(url)` is a small pure host→provider map **inside `savefile.py`** — `music.youtube.com`→`youtube-music`, `youtube.com`/`youtu.be`→`youtube`, `soundcloud.com`→`soundcloud`, `*.bandcamp.com`→`bandcamp` — with the pinned fallback **`"youtube"`** for any unrecognized host. Why a local map and not core URL parsing: the CLI cannot import `spotdl_core.providers.parse` (import-linter `no_cli_core`), and this field is display/provenance metadata only — `sync` re-resolves/re-matches through the server anyway, so a fallback misattribution is harmless and never blocks loading. Why `"youtube"` as fallback: v4's `download_url` came from its audio providers (YouTube Music default), so any unmapped host is overwhelmingly a YouTube-family URL. |
| `download` | — | synthesize `SaveFileDownload{output_format=<from ext or "mp3">, bitrate="auto", output_template=<config default>, status="queued"}` (v4 files record no per-song download result) |

Top-level `SaveFileV2`: `version=2`; `kind` inferred (`playlist` if any song has `list_name`, else `album` if all share `album_name`, else `single`); `name` = first `list_name`/`album_name`; `source=null`; `created_at` = file mtime ISO; `matcher_version=null`; `songs=[...]`. Migration is **in-memory only** unless the command writes a new `.spotdl` (then it is v2). A test round-trips a captured v4 fixture.
