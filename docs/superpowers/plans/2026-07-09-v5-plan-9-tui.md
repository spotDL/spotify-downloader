# spotDL v5 `apps/cli` — Textual TUI over shared view-models (Plan 9 of 11)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `spotdl tui` command of spec §7 — a **Textual** terminal UI with **full parity to the web UI** (spec §8): home/search, entity pages (track/album/artist/playlist), match voting + submit-URL, lyrics (incl. synced display), download queue with live WebSocket progress + cancel, settings, auth (login/status/logout/register), and admin-lite (reports queue). The TUI is a **pure presentation layer**. It ships: (1) a **`viewmodels/` package** — pure, framework-free classes that consume the Plan 8 `SpotdlClient` façade and return display-ready snapshots; **all fetching, reducing, formatting, validation, and feature-gating lives here** and is unit-tested against a fake client; (2) a **`tui/` package** — the Textual `App`, one `.tcss`, a screen inventory with **hard per-file line budgets**, a navigation/router model, and a small set of **reusable widgets** (entity card, match gauge + vote buttons, lyrics pane with synced highlight, queue table with progress, settings form, status bar); (3) the real **`spotdl tui`** command (replaces Plan 8's stub) wired to the bare-`spotdl`-in-a-TTY dispatch Plan 8 added; (4) a **bounded extension** of Plan 8's `client.py`/`views.py` — thin 1:1 passthrough methods + `*View` mappers for server endpoints that already exist (Plans 6/7) but the Plan 8 CLI didn't surface (admin reports queue, `POST /reports`, `GET /reports/me`, `POST /auth/register`, the embedded/download transport's `GET /config`); and (5) **machine-enforced discipline** — an import guard (TUI imports only `textual`/`rich`/`viewmodels`; view-models import no `textual`/generated-client/`httpx`/`spotdl_server`) plus a size-budget CI test.

**Architecture (HARD RULE — spec §7/§13, machine-enforced):** the dependency direction *inside* `apps/cli` is `tui → viewmodels → SpotdlClient → _generated client → server API`. **No provider/matching/download logic ever lives in TUI code**, and no such logic is *added* to the CLI at all: the TUI's data needs are met by the server API that Plans 5–7 already expose, surfaced through the shared `SpotdlClient` façade (Plan 8). New data needs would grow the **server** API (benefiting web too), never the TUI. Concretely: **Textual screens and widgets may import only `textual`, `rich`, and `spotdl_cli.viewmodels`** — never the generated client, `httpx`, `spotdl_server`, or even `spotdl_cli.client`/`transport` directly. **View-models may import only `spotdl_cli.views`, `spotdl_cli.errors`, `spotdl_cli.config`, and the standard library** — never `textual` (proving they are framework-free and portable to the web-parity story), never the generated client, `httpx`, or `spotdl_server`; they reach the server exclusively through a structural `SpotdlClientProtocol`. The one construction seam — building the real `SpotdlClient` and injecting it — lives in the `spotdl tui` command (`commands/tui.py`), the layer already allowed (Plan 8) to touch `SpotdlClient.from_config`. This is the direct mitigation for spec §13's "TUI parity balloons" row (the abandoned rewrite branch's TUI was **16,588 lines** with a 1,738-line `api_client.py` and a 1,605-line settings screen — see the anti-pattern reference below).

**Tech Stack:** Python 3.13, **Textual `>=1.0`** (TUI framework, new CLI runtime dep), Rich (already a dep, used for in-widget renderables). Dev/test only (root dev group): **textual-dev `>=1.7`** (the `textual` devtools + `run` harness) and **pytest-textual-snapshot `>=1.0`** (optional SVG snapshot regression — see CONTRACT I policy). View-models are plain `asyncio` + `dataclasses`/`pydantic` and consume the Plan 8 façade only. Tests: pytest + pytest-asyncio; **view-models are unit-tested against an in-memory `FakeSpotdlClient`** implementing `SpotdlClientProtocol` (canned `*View` data + a controllable WS frame source); **screens/widgets are driven by Textual's `App.run_test()` pilot harness** against the same fake. The default suite is **fully offline**: no real `SpotdlClient`, no embedded server, no network, no terminal — Textual's headless driver + the fake client only.

## Bounded exception this plan MUST make explicit (CONTRACT H — read before Task 1)

Plan 8's self-review states Plan 9 "adds no new transport or client code." That held for the CLI's command set, but **the TUI has full web parity** (admin-lite + reports) that the Plan 8 commands never surfaced, and the queue-availability gate needs the **download/embedded transport's** `GET /config`. Those endpoints **already exist** on the server (Plans 6/7); they were simply not exposed through the façade. Resolving this honestly:

**Plan 9 extends `spotdl_cli/client.py` and `spotdl_cli/views.py` with THIN, 1:1 passthrough methods + `*View` mappers ONLY** — the exact pattern of Plan 8 CONTRACT B — for endpoints that already exist server-side:
- `download_config() -> ConfigView` — `GET /config` on the **download (embedded) transport** (the resolution `config()` already exists; this is the sibling for the always-embedded transport, so the TUI can gate the queue on the download engine's `features.downloads`).
- `register(email, password) -> Tokens` — `POST /auth/register` (resolution/community transport; sibling of `login_password`).
- `submit_report(subject_type, subject_id, *, field=None, proposed_value=None, reason=None) -> ReportView` — `POST /reports`.
- `my_reports() -> list[ReportView]` — `GET /reports/me`.
- `admin_reports(*, status="pending") -> list[ReportView]` — `GET /admin/reports`.
- `approve_report(id, *, note=None) -> ReportView` / `reject_report(id, *, note=None) -> ReportView` — `POST /admin/reports/{id}/approve|reject`.
- `admin_stats() -> StatsView` — `GET /admin/stats`.
- New `*View` types in `views.py`: `ReportView`, `StatsView` (frozen, `from_generated` mappers, same standards). `ReportView.subject_type` (and the `submit_report` parameter) is a **view-facing `str`** — the string value of the server's `EntityType` enum — deliberately distinct from any generated enum type; the façade maps/validates it against the generated request model, per rule A.3 (no generated types cross the view boundary).

**Deliberately NOT added:** `vote_link` / `POST /links/{id}/vote`. No web-parity page (spec §8) surfaces cross-provider link voting, so no TUI screen consumes it — adding the passthrough would be dead code (spec §13: "dead layers accumulate"). If a future entity page grows a link-voting surface, the method is a one-line CONTRACT H-style addition then.

**This adds NO transport, NO connectivity policy, NO business logic** — each method is one generated-op call + one `*View` mapping + the shared `ApiError` translation, identical to Plan 8's existing façade methods. It does **not** change the HARD RULE (TUI → view-models → façade → server). A guard test (`test_client_extension.py`) asserts each new method is a thin wrapper (no new imports beyond what Plan 8 used; no `spotdl_core`). This is the spec §7 "data needs grow the server API" path — here the API already grew; we only surface it through the shared client.

## THE CONTRACTS (authoritative — verbatim; implementers copy, only internals are free)

### CONTRACT A — The view-model layer (`spotdl_cli/viewmodels/`) — pure, framework-free

**Rules (all machine- or test-enforced):**
1. View-models import **only** the stdlib, `spotdl_cli.views`, `spotdl_cli.errors`, `spotdl_cli.config`, and `typing`. **Never `textual`, never `spotdl_cli._generated`/`client`/`transport`, never `httpx`/`spotdl_server`.** They reach the server solely through the injected `SpotdlClientProtocol` (CONTRACT I `viewmodels_framework_free` guard).
2. Every remote call is wrapped so `ApiError` (and connection errors) become a `Loadable.failed(ErrorDisplay)` — a view-model **never raises to the screen**; it returns a snapshot whose `state == ERROR`. Screens render the error via the toast (CONTRACT G).
3. View-models hold state as **immutable snapshots** (frozen dataclasses); mutating methods return the new snapshot. No FastAPI/ORM/generated types cross the view-model boundary — only `views.*` in, `viewmodels.types.*` out.
4. Pure transforms (duration formatting, score→gauge %, LRC parsing, active-synced-line, WS frame reduction, config-field validation) are **plain functions/methods** unit-tested directly.

```python
# viewmodels/base.py
class LoadState(StrEnum): IDLE="idle"; LOADING="loading"; READY="ready"; ERROR="error"

@dataclass(frozen=True, slots=True)
class ErrorDisplay:
    message: str                       # from describe_api_error (CONTRACT G / Plan 8 CONTRACT E table)
    code: str | None                   # ErrorCode value, or None for a non-API/connection error
    severity: Literal["error","warning"]

@dataclass(frozen=True, slots=True)
class Loadable(Generic[T]):
    state: LoadState
    data: T | None = None
    error: ErrorDisplay | None = None
    @classmethod
    def loading(cls) -> "Loadable[T]": ...
    @classmethod
    def ready(cls, data: T) -> "Loadable[T]": ...
    @classmethod
    def failed(cls, err: ErrorDisplay) -> "Loadable[T]": ...

async def guard(coro: Awaitable[T]) -> Loadable[T]:
    """Await coro; map ApiError/connection errors → Loadable.failed(describe(...)). The ONE place
    every view-model funnels remote calls through (rule A.2)."""
```

### CONTRACT C — Navigation model (screens, bindings, router, base screen)

- **Screen stack** (Textual `push_screen`/`pop_screen`). Top-level **sections** are switched (`app.switch_section(name)` → `switch_screen`); **entity detail** screens are **pushed** (drill-down) and `escape` pops. The stack gives free "back" for home→track→album navigation.
- **`SpotdlScreen(Screen)` base** — all screens subclass it. It mounts a persistent `StatusBar` (top) + `Footer` (key hints, bottom), exposes `self.app.show_error(err)` and `self.vm_factory`, and declares the **global bindings** so subclasses stay tiny:

| Key | Action | Scope |
|---|---|---|
| `1` | Home / search | global section switch |
| `2` | Queue | global (hidden/disabled when `session.can_download` is False) |
| `3` | Settings | global |
| `4` | Account (auth) | global (disabled when `session.can_auth` is False) |
| `5` | Admin | global (shown only when `session.is_admin`) |
| `/` | focus the search input (switches to Home first if needed) | global |
| `escape` | back (`pop_screen`; on a section root, no-op) | global |
| `?` | Help overlay | global |
| `q` / `ctrl+c` | quit | global |

Per-screen context bindings (declared on each screen, shown in its Footer): Track → `u`/`d`/`r` vote up/down/retract the focused match, `enter` open focused match URL detail, `m` submit-match URL prompt, `e` enqueue this track, `[`/`]` cycle lyrics source, `space` toggle synced follow; Collection → `e` enqueue all, `enter` enqueue focused track; Queue → `x` cancel focused job, `enter` job detail; Admin → `a`/`x` approve/reject focused report. Bindings that require a disabled feature are **not registered** when the flag is off (they never appear in the Footer) — see CONTRACT F.
- **`tui/router.py`** — `open_entity(app, ref: EntityRef)` maps `ref.entity_type` → `{track: TrackScreen, album: AlbumScreen, artist: ArtistScreen, playlist: PlaylistScreen}` and pushes it with `ref.id`. Pure dispatch, no fetching. `resolve`-then-route: `HomeSearchScreen` calls `SearchViewModel.open(query)`; on `Loadable.ready(ref)` it posts `NavigateTo(ref)`; `SpotdlApp` handles it via `router.open_entity`.

### CONTRACT D — Reusable widget strategy (`tui/widgets/`)

Shared widgets are **dumb**: constructed with a display dataclass (or a `session` flag), they render and emit a `Message` on interaction; they never fetch or transform data (a pure formatting call into a view-model `@staticmethod` is allowed).

- **`EntityCard(EntityHeader)`** — cover placeholder + title + subtitle + a row of stat chips. Used by Track/Album/Artist/Playlist.
- **`MatchGauge(MatchRow, *, can_vote: bool)`** — a 0–100 horizontal score bar + status badge (`auto`/`verified`/`rejected`) + tallies; **vote buttons (up/down/retract) rendered only when `can_vote`**. Emits `VoteRequested(match_id, value)`.
- **`LyricsPane(*, can_vote: bool)`** — sets a `choices: list[LyricsChoice]` reactive; a source selector (`[`/`]`); a scrollable body. For **synced** lyrics it holds a `reactive position_ms` and highlights the line returned by `TrackViewModel.active_synced_line(choice, position_ms)` (pure); `space` toggles a follow-clock (simulated play-head since the TUI has no audio) that advances `position_ms`. Vote buttons gated by `can_vote`; emits `VoteRequested` with the lyrics id.
- **`QueueTable`** — a `DataTable` subclass; `update(snapshot: QueueSnapshot)` diffs rows and renders a Rich progress cell per job (phase + percent) + status glyph. Emits `CancelRequested(job_id)` on `x`.
- **`SettingsForm`** — renders `tuple[SettingField,...]` as labeled inputs / `Select`s (choice fields) / `Switch`es (bool); emits `FieldChanged(key, raw)` on edit and a save action; shows per-field validation errors returned by `SettingsViewModel.set`.
- **`StatusBar`** — reads `SessionSnapshot`: auth indicator (`user_email` or `guest`), `transport_label`, `mode`, a `degraded` badge, `matcher_version`. Updated when the app's `session` reactive changes.

Widgets and their messages live under `tui/widgets/` and `tui/messages.py`; screens wire message handlers to view-model calls.

### CONTRACT E — WebSocket consumption pattern (background worker → reactive updates)

The queue is the only live surface. Pattern (single code path for local + remote, since `SpotdlClient.progress()` already unifies them):

1. `QueueScreen.on_mount` seeds state with `await vm.load()` (a `list_downloads()` snapshot), sets `self.snapshot` (a `reactive[QueueSnapshot]`), then starts a **Textual worker**: `self.run_worker(self._consume(), exclusive=True, group="ws", name="queue-ws")`.
2. `_consume` is `async for update in self.vm.stream():` — the **view-model** owns `SpotdlClient.progress()`, applies the **pure `reduce`** per frame, checks `WsHello.protocol_version` (mismatch → yields one `Loadable.failed`), and handles bounded reconnect/backoff. The worker never parses frames itself.
3. On each yielded `Loadable`: `ready` → set `self.snapshot = update.data` (a reactive assignment); `watch_snapshot` calls `self.query_one(QueueTable).update(snapshot)` and refreshes the `StatusBar` counts. `failed` → `self.app.show_error(update.error)` (toast) and, for a protocol mismatch, stop the worker.
4. Worker lifecycle: Textual cancels workers on screen unmount; `stream()` closes the `progress()` context on cancellation (`finally`). No thread juggling — workers run on the app event loop, so reactive assignment is safe without `call_from_thread`.
5. **Enqueue → live update:** enqueue actions (`QueueViewModel.enqueue`, `TrackViewModel.enqueue`, `CollectionViewModel.enqueue_all`) call `submit_download`; the resulting jobs stream in through the already-running `/ws/progress` fan-out, so the queue updates without a manual refetch.

Unit-testable core: `reduce(snapshot, msg)` is pure and covered with synthetic frame sequences (queued→started→progress→finished / →failed / →cancelled / →batch_finished, out-of-order and duplicate frames). Pilot test feeds frames through `FakeSpotdlClient.progress()` (a test-controlled async source) and asserts `QueueTable` rows.

### CONTRACT F — Feature/mode-awareness gating (driven by `GET /config`)

`AppStateViewModel.load` fetches the **resolution** `config()` and the **download/embedded** `download_config()` (+ `me()` if a token is stored) into a `SessionSnapshot`. Screens/widgets read the snapshot; **gating is done once, at mount, by hiding/omitting — never by per-request server errors leaking to the user.**

| Flag (source) | When False → the TUI |
|---|---|
| `can_vote` = resolution `config().features.voting` | hides vote buttons on `MatchGauge` + `LyricsPane`; hides submit-match (`m`) + report actions; the vote/submit bindings are not registered |
| `can_auth` = resolution `config().features.auth` | disables the Account section (`4`); `AuthViewModel` methods short-circuit to `ErrorDisplay(OFFLINE_AUTH_MESSAGE)` — the exact CONTRACT A literal `sign-in needs the community server; it's unavailable offline` |
| `can_download` = **download** `download_config().features.downloads` | hides the Queue section (`2`) + all enqueue actions/bindings (Track `e`, Collection `e`/enqueue-track) |
| `is_admin` = `me().is_admin` | Admin section (`5`) is only installed/shown when True |
| `degraded` (from resolve/config) | `StatusBar` shows a "metadata may be thinner" badge (spec §10 visible degradation) |

Because downloads are **always embedded** (Plan 8), `can_download` is True on a normal CLI install (embedded `features.downloads` = mode ≠ HOSTED = True); it is False only in a hypothetical hosted-only build where no embedded engine boots — exactly the "downloads hidden in hosted-remote-only" case. `can_vote`/`can_auth` are False whenever resolution is embedded/offline (embedded mode = authless, spec §4), so the offline TUI is read + local-download only, with voting/auth cleanly hidden.

### CONTRACT G — Error toast (reuse Plan 8's envelope table; ONE source of truth)

Task 1 refactors Plan 8 `errors.py`: extract a **pure** `describe_api_error(err: ApiError) -> ErrorRendering(message: str, exit_code: ExitCode)` implementing the CONTRACT E table (exhaustive over `ErrorCode`, same `server error ({code})` fallback). `render_api_error` (CLI) becomes `describe` + print + exit — its behavior and the exit-code table are **unchanged** (a Plan-8 regression test re-asserts every row). The view-model layer maps `describe(...)` (plus connection errors) into `ErrorDisplay(message, code, severity)`: `severity = "warning"` for `provider_unavailable`, `rate_limited`, and degraded notices; `"error"` otherwise. `SpotdlApp.show_error(err: ErrorDisplay)` calls Textual's `self.notify(err.message, severity=("warning" if err.severity=="warning" else "error"), title="spotDL")`. **No separate error message strings exist in `tui/`** — the toast text comes from the shared table, so CLI and TUI never drift.
